\section{Problem Formulation}
\label{sec:problem}

\subsection{Longitudinal Proactive Assistance}

Let a session be an ordered stream of events $E=(e_1,\ldots,e_T)$.
Each event is represented as
\begin{equation}
e_t=(\tau_t,a_t,v_t,o_t,m_t)
\end{equation}
Here, $\tau_t$ is time, $a_t$ is the actor, $v_t$ is an action verb, $o_t$ is an object or entity, and $m_t$ contains domain metadata.
Structured tool calls are mapped deterministically; free-form language can be parsed into the same schema by an LLM.
The benchmark uses pre-structured events to isolate habit induction and intervention control from event parsing.

Before turn $t$, an agent maintains a method-dependent state $S_t$ derived from prior events $e_{<t}$.
The state may contain raw observations, retrieved memories, summaries, or learned behavioral representations; the task definition does not prescribe its form.
After observing the current event, the agent chooses whether to intervene:
\begin{equation}
(\hat{y}_t,\hat{p}_t)=\pi(e_t,S_t),
\qquad \hat{y}_t\in\{0,1\}.
\end{equation}
Here, $\hat{y}_t=1$ denotes a proactive intervention and $\hat{y}_t=0$ denotes abstention; $\hat{p}_t$ is the proposed service when an intervention is made and is empty otherwise.
The current event is incorporated into persistent state only after this decision, preventing it from appearing as its own historical evidence:
\begin{equation}
S_{t+1}=U(S_t,e_t).
\end{equation}

We adopt the observe--propose-or-abstain structure used in prior proactive agent work~\citep{lu2025proactiveagent}.
Our benchmark labels whether an intervention opportunity exists at each turn independently of proposal wording, allowing intervention timing and abstention to be evaluated separately from downstream language realization.

\subsection{Evaluation Objective}

Each evaluation turn has a ground-truth label $y_t$ indicating whether an intervention is useful at that stage.
We report precision, recall, F1, false positives (FP), and Push count in the main text; complete traces additionally retain accuracy and true-positive, false-negative, and true-negative counts.
F1 captures the balance between recovering useful interventions and avoiding false ones, while FP and Push count operationalize false and total intervention frequency.
Because the relative cost of missed and unnecessary interventions is deployment dependent, we treat threshold and cooldown as an operating policy and report their resulting accuracy--intervention trade-off.
